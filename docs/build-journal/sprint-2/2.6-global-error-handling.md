# Task 2.6: Global error handling

> **Sprint:** 2 · **Commit:** `Sprint 2.6: Add global error handling` · **Status:** done (all six Done-when items met; `./gradlew build` passes with 219 tests; the spec review asked for changes, made in a close-out pass, see §9) · **Time taken:** roughly 1 hour 5 minutes for the build by the machine clock (21:03 to about 22:10 on 2026-10-30), including the experiments, the mutation checks, two full builds and this entry, plus about 25 minutes for the fix pass (22:45 to about 23:10)
> **Built:** every error the API can answer with now has one shape and one place that makes it. `common/GlobalExceptionHandler` (extended, not replaced) turns nine new domain exceptions and Spring's own exceptions into the RFC 9457 problems listed in the API contract, with `fieldErrors` for validation, no stack trace, SQL or echoed input in a response and no exception message in the log, and 55 new tests that prove it, including a real Hibernate race, a real 25 MB upload and two real Postgres errors.

## 3. The plan
1. **Contract first.** Add the missing rows and the list of promises to API_CONTRACT (the rules say contract before code).
2. **`ProblemKind` and the nine exceptions.** They are the vocabulary the handler and the tests use.
3. **`FieldErrors`** with its own plain unit test, because it is pure logic.
4. **The handler**, rewritten to extend `ResponseEntityExceptionHandler`.
5. **The web-slice test**: one controller that throws on request and validates a body, with the contract's strings as literals. It found three of the problems in §8.
6. **The real-app test** for what a slice can't show: Hibernate's real exception, Tomcat's real size limit, Postgres's real error, springdoc.
7. **Break it on purpose** (mutation checks), **boot the app** against Compose and `curl` it, update the docs, run the full build.

The order matters in one place: the slice test came before the real-app test because its failures were cheap to read (a few seconds, no Docker) and they changed the handler's design twice before I paid for a Postgres container.

## 5. How it was built

**The contract** ([`API_CONTRACT.md`](../../API_CONTRACT.md#errors-rfc-9457-problemdetail), Errors)
Two rows (`method-not-allowed`, `not-acceptable`), wider wording on three (`malformed-request` now includes a missing required parameter, `not-found` a path that doesn't exist, `unsupported-media-type` a wrong request Content-Type), and a list of what every error response promises: same fields, how `fieldErrors` is built, English, nothing the client sent comes back, nothing from the server comes out, Spring's own errors keep their status, the two causes of `entry-stale`, and the far-over-limit upload caveat. The file has CRLF line endings, which Git Bash's `grep` hides, so I edited it with the Edit tool and checked `git diff --stat` (15 insertions, 3 deletions).

**The problem kinds** ([`ProblemKind.java:12-90`](../../../backend/src/main/java/com/memoirist/common/ProblemKind.java#L12-L90))
An enum with a constructor and four fields. The default detail of each is a sentence safe to show to anyone. It is package-private; the tests use literal strings so that renaming a constant changes nothing a client sees.

**The exceptions** (nine files in [`common/`](../../../backend/src/main/java/com/memoirist/common/))
Each is a few lines and a Javadoc that says what throws it, what status it becomes and what its message may contain. The rule is written on each: `NotFoundException` takes a resource word and makes `"Entry not found."`; `StorageUnavailableException` always carries a cause because the cause names the storage host; `ConflictException`'s message never says who owns the other row.

**`FieldErrors`** ([`FieldErrors.java:21-65`](../../../backend/src/main/java/com/memoirist/common/FieldErrors.java#L21-L65))
Two collections: a `TreeMap<String, TreeSet<String>>` of messages per field and a `TreeSet` of messages for no field. `add` is `computeIfAbsent(...).add(...)`; `asMap` joins each set with `; `. The practice block is `add` and `asMap` ([lines 32-47](../../../backend/src/main/java/com/memoirist/common/FieldErrors.java#L32-L47)). A null message becomes `"is invalid"`, because Spring's `getDefaultMessage()` is nullable.

**The handler** ([`GlobalExceptionHandler.java`](../../../backend/src/main/java/com/memoirist/common/GlobalExceptionHandler.java))
Read it in four blocks:
- [Lines 65-149](../../../backend/src/main/java/com/memoirist/common/GlobalExceptionHandler.java#L65-L149): our own exceptions. Each handler returns a `ProblemDetail`. `entryStale` listens for two exception classes ([line 100](../../../backend/src/main/java/com/memoirist/common/GlobalExceptionHandler.java#L100)) and ignores their messages. The catch-all ([lines 135-149](../../../backend/src/main/java/com/memoirist/common/GlobalExceptionHandler.java#L135-L149)) logs `ScrubbedException.of(exception)` (the classes, the SQLState and the frames, no message; the other three log sites do the same) and answers with the fixed sentence. In the first version it logged the whole exception, message included (decision 15, §9).
- [Lines 151-229](../../../backend/src/main/java/com/memoirist/common/GlobalExceptionHandler.java#L151-L229): overrides for Spring's exceptions where the default isn't enough: a `@Valid` body (`MethodArgumentNotValidException`), a constraint on a parameter (`HandlerMethodValidationException`, which has to be walked as `ParameterErrors` or plain `ParameterValidationResult`), a path variable that won't convert, a missing parameter or part.
- [Lines 231-249](../../../backend/src/main/java/com/memoirist/common/GlobalExceptionHandler.java#L231-L249): `handleExceptionInternal`. *Every* response Spring builds for itself passes through here, including the overrides above. It calls `super`, then dresses the `ProblemDetail`: our type, title and fixed detail for its status, and a `timestamp`. It logs any 5xx.
- [Lines 251-318](../../../backend/src/main/java/com/memoirist/common/GlobalExceptionHandler.java#L251-L318): `problem(kind, detail)`, `hasOurType` (Spring 7's "no type yet" is `null`), and `kindFor(status)`, a `switch` expression from a status to a kind (a status the contract doesn't list returns `null` and keeps `about:blank`; since the fix pass only `500` becomes `internal-error`).

**`ScrubbedException`** ([`ScrubbedException.java`](../../../backend/src/main/java/com/memoirist/common/ScrubbedException.java), added in the fix pass)
What the log gets in place of an exception. `of(original)` walks the cause chain (at most 20 links, and a loop is cut) and builds one `ScrubbedException` per link whose message is the original's *class name*, plus ` (SQLState 23514)` for a `SQLException`. It copies the stack frames with `setStackTrace`, passes `enableSuppression = false` to the four-argument `RuntimeException` constructor so suppressed exceptions (which carry messages) are not kept, and never calls `getMessage()` or `toString()` on what it copies. Logback prints it as `com.memoirist.common.ScrubbedException: org.postgresql.util.PSQLException (SQLState 23514)` with the frames and `Caused by:` lines.

**Configuration** ([`application.yml:50-67`](../../../backend/src/main/resources/application.yml#L50-L67))
`spring.web.locale-resolver: fixed` and `locale: en`, and `spring.web.error.include-stacktrace/exception/message/binding-errors` set to the safe values, each with a comment saying why. At the top of the file ([lines 3-13](../../../backend/src/main/resources/application.yml#L3-L13)) `logging.level.org.hibernate.orm.jdbc.error: "off"`, added in the fix pass (decision 18).

**The tests** (§6) and the docs (TECH_STACK §2 Errors, Multipart limits; API_CONTRACT).

## 6. How it was tested
- **Strategy:** four layers, fastest first.
  1. Plain unit tests for pure logic (`FieldErrors`, `ScrubbedException`, `ProblemKind` against the contract).
  2. A web slice (`@WebMvcTest` with a test-only controller) for the *mapping*: every type over HTTP, with hand-made exceptions, no Docker.
  3. The whole app (`@IntegrationTest`) for the *real* exceptions that only Hibernate, Tomcat and Postgres produce.
  4. A mutation check for each decision that mattered: break the code, see which test notices (below).
- **Why a second integration context.** `ErrorHandlingIntegrationTest` adds a test-only controller with `@Import`, so Spring caches it as its own context with its own Postgres container (about 10 seconds extra). The alternative was adding the controller to `@IntegrationTest`, which would put it in every integration test.

## 10. Concepts to learn from this task
- **`@RestControllerAdvice` and "closest match wins"** ([`GlobalExceptionHandler.java:49-50`](../../../backend/src/main/java/com/memoirist/common/GlobalExceptionHandler.java#L49-L50)): one class whose `@ExceptionHandler` methods apply to every controller. For a given exception Spring picks the handler whose declared type is nearest in the class hierarchy, so a handler for `NotFoundException` beats one for `Exception`. The mistake: assuming a catch-all only sees "unknown" exceptions. Spring's own `NoResourceFoundException` is also "unknown" to a plain advice.
- **`ResponseEntityExceptionHandler`** ([line 50](../../../backend/src/main/java/com/memoirist/common/GlobalExceptionHandler.java#L50)): Spring's ready-made advice for the exceptions MVC raises (wrong method, unreadable body, unknown path...). Subclass it, override the `handleXxx` you need, and funnel everything through `handleExceptionInternal`. Its `handleException` is `final`; you extend by overriding the protected methods.
- **`ProblemDetail` / RFC 9457** ([`problem(...)` at line 269](../../../backend/src/main/java/com/memoirist/common/GlobalExceptionHandler.java#L269)): a standard JSON error body (`type`, `title`, `status`, `detail`, `instance`) served as `application/problem+json`, with extension members via `setProperty` (`timestamp`, `fieldErrors`). In Spring 7 an unset `type` is `null`, which Jackson omits; clients read the absence as `about:blank`.
- **Bean validation's two exceptions** ([lines 153-196](../../../backend/src/main/java/com/memoirist/common/GlobalExceptionHandler.java#L153-L196)): a failing `@Valid @RequestBody` throws `MethodArgumentNotValidException` (with a `BindingResult` of `FieldError`s); a failing constraint on a parameter (`@RequestParam @Min(0) int page`) throws `HandlerMethodValidationException` (with a list of `ParameterValidationResult`). Different shapes, same answer. The mistake: handling only the first and shipping a `500` for a bad query parameter.
- **Optimistic locking, from the exception's side** ([line 100](../../../backend/src/main/java/com/memoirist/common/GlobalExceptionHandler.java#L100)): Hibernate runs `UPDATE ... WHERE id=? AND version=?`, sees 0 rows, throws `StaleObjectStateException`, and Spring translates it to `ObjectOptimisticLockingFailureException`. It is thrown at flush/commit, which may be after your service method returned, which is why the comparison in the service isn't enough.
- **Enums with fields** ([`ProblemKind.java:12`](../../../backend/src/main/java/com/memoirist/common/ProblemKind.java#L12)): constants that carry data, with a private constructor. Good for a closed list that has attributes (here suffix, status, title, detail).
- **Switch expressions and pattern matching** ([`kindFor` at line 306](../../../backend/src/main/java/com/memoirist/common/GlobalExceptionHandler.java#L306), and `instanceof ParameterErrors parameterErrors` at line 178): `switch` that returns a value, with `->` arms and a `default`; `instanceof` that declares the variable in the same expression. Both avoid casts and fall-through.
- **`Map.computeIfAbsent`, `TreeMap`, `TreeSet`** ([`FieldErrors.java:38-45`](../../../backend/src/main/java/com/memoirist/common/FieldErrors.java#L38-L45)): get-or-create a bucket in one call; sorted collections give a stable order and remove duplicates. Mistake: a `HashMap` here makes the JSON field order depend on the JVM.
- **`@TestComponent` and a test-only controller** ([`GlobalExceptionHandlerTest.java:453`](../../../backend/src/test/java/com/memoirist/common/GlobalExceptionHandlerTest.java#L453)): a bean that component scanning skips, brought in with `@Import` for one test class. It lets you test HTTP behaviour before any real endpoint exists.
- **`OutputCaptureExtension` / `CapturedOutput`** ([`GlobalExceptionHandlerTest.java:310-337`](../../../backend/src/test/java/com/memoirist/common/GlobalExceptionHandlerTest.java#L310-L337)): JUnit extension that gives a test what was written to the console so far. The way to assert on a log line without a custom appender.
- **What a log may hold** ([`ScrubbedException.java`](../../../backend/src/main/java/com/memoirist/common/ScrubbedException.java)): an exception's `getMessage()` is free text written by whoever threw it, and a database driver puts the failing row in it. So a log line is as sensitive as a response. The pattern: log the *kind* of failure (class names, a standard code such as SQLState) and *where* (stack frames), never the message. The four-argument `RuntimeException(message, cause, enableSuppression, writableStackTrace)` constructor lets a copy drop suppressed exceptions and still take the original's frames. The mistake: fixing your own `log.error(...)` and forgetting that Hibernate logs the same message on its own logger (`org.hibernate.orm.jdbc.error`); only a test that reads the whole log finds that.
- **JsonPath's `DocumentContext`** ([`assertProblem`, line 408](../../../backend/src/test/java/com/memoirist/common/GlobalExceptionHandlerTest.java#L408)): parse a response body once and `read("$.fieldErrors")` as a typed value, so AssertJ can compare maps and strings with readable failures.
- **`LocaleResolver` and `spring.web.locale-resolver=fixed`** ([`application.yml:54`](../../../backend/src/main/resources/application.yml#L54)): by default Spring uses `Accept-Language`; `fixed` makes every request English. Validation messages follow the locale of the request.
- **Tomcat's swallow limit** (§8 item 5): when a server rejects a request before reading all of it, it may have to read and discard the rest to keep the connection usable. `max-swallow-size` caps that; past it, the connection is closed, and the client may never see the response.
- **springdoc and `@ResponseStatus`** ([`ErrorHandlingIntegrationTest.java:269`](../../../backend/src/test/java/com/memoirist/common/ErrorHandlingIntegrationTest.java#L269)): springdoc copies the response codes of advice handlers into every operation, so one stray annotation documents an error on every endpoint.

## 12. At work
- **One error contract for the whole API.** In an enterprise Spring codebase the same thing is usually a shared library or a base `@ControllerAdvice` that every service uses, so that a front end and an API gateway parse one shape. A reviewer asks: does every error have a stable machine-readable code (`type`), separate from the human sentence? Are 4xx and 5xx clearly different in what they reveal?
- **Information disclosure is a finding, not a style point.** Stack traces, SQL, constraint names, class names and "user not found" versus "wrong password" are all things a penetration test reports (OWASP API security calls it improper error handling / excessive data exposure). A reviewer greps for `getMessage()` in a response, for `include-stacktrace`, and for a catch-all that returns `e.toString()`. The tests here pin the absence.
- **Log the cause, return a sentence, and keep the data out of the log.** The usual extra at a bank is a correlation id: the response carries an id, the log line has the same id, support can find the stack from the customer's screenshot. It was left out here (a single-user local app) and is one `setProperty` away. The other half is what the log may hold: at a bank the review question is "does any log line contain customer data?", and an exception message from a database driver does (here, the whole failing row). Log the exception class, a standard error code and the frames, as `ScrubbedException` does, and test the whole log, because the ORM writes its own copy.
- **Input reflection.** Echoing a rejected value into an error message is how reflected XSS and log forging start. Keeping messages to field names and rules is cheap; a reviewer looks for string concatenation of request data into a response or a log.
- **Optimistic locking and `409`/`412`.** Two people editing one record is normal in a banking back office. The same exception (`OptimisticLockingFailureException`) appears with Spring Data JPA's `@Version`. Teams answer `409`, or `412` with an `ETag`/`If-Match` header. The review question is whether the stale-update path is tested against the *real* exception, which is what the race test here does.
- **Catch-all handlers.** A catch-all is correct and also dangerous: it hides bugs if it doesn't log, and it hijacks framework errors if the class doesn't extend the base. A reviewer checks both: is the failure logged (class and stack, without a message that may hold data), and does a wrong URL still give `404`?
- **Locale.** Services behind a bank's front end often pin the language of machine-readable messages and translate in the client, for exactly the reason in §8 item 3.
- **Test the contract, not the code.** The test that compares the contract table with the enum is the kind of cheap guard that stops documentation drifting in a team of many.

1. A plain advice with a catch-all also catches Spring's own exceptions, such as `NoResourceFoundException` (unknown path) and `HttpRequestMethodNotSupportedException`, and answers `500` for them. The experiment: `GET /nothing -> 500` and `DELETE /only-get -> 500`. Extending `ResponseEntityExceptionHandler` makes Spring's exceptions go to its own handlers (right status), and the catch-all only sees what is left.
2. `NotFoundException`'s handler. Spring picks the `@ExceptionHandler` whose exception type is the closest to the thrown one in the class hierarchy (depth 0 beats depth 1).
3. Another request committed between the service's check and this request's commit. Hibernate's `UPDATE ... WHERE id = ? 5. `must not be blank; size must be between 3 and 150`. `FieldErrors` keeps a `TreeSet` of messages per field and a `TreeMap` of fields, so the order is alphabetical and doesn't depend on the order in which Spring reports the failures. (Duplicates are removed by the set too.)

7.
