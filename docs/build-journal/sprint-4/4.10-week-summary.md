## 5. How it was built
1. **`frontend/src/lib/displayTitle.ts`**
   - `linesOf` (`:31`) flattens a checked TipTap tree (`toNode` from 4.5) into `{ text, heading }` lines, one per paragraph, heading and hard break; lists and quotes just recurse.
   - `previewLine` (`:65`, a practice block) is one pass: return the first non-heading line with text, remember the first heading with `??=`, cut to 120 code points with `Array.from`.
   - `entryDisplayTitle` (`:95`) returns `null` for any `isLocked` entry before reading anything, then reuses the existing `displayTitle` for summaries, so there is one ordering rule.
2. **`frontend/src/lib/time.ts:315`**: `barDay("2026-10-19")` is "Mon 19". The week's dates reuse `formatEraDates` ("19–25 Oct 2026").
3. **`frontend/src/features/week/summary.ts:38`**: `summarise` (a practice block) filters out sealed entries, then counts pictures and voice notes, keeps ten thumbnails, and counts tags in a `Map`, sorted by count then name. `mediaCounts` (`:75`) feeds each bar.
4. **`frontend/src/api/queryKeys.ts:35-36`** (`weeks()` and `week(id)` under it) and **`frontend/src/api/weeks.ts`**: `weekQuery`/`useWeek` (`:11`, `:23`), `useRenameWeek` (`:42`) sends the soundtrack back (full replace, D-26), `useSetWeekClosed` (`:66`) calls `close` or `reopen`.
5. **`frontend/src/features/week/WeekSummaryPage.tsx`**
   - `WeekSummaryPage` (`:31`): a 404 says "This week isn’t in your journal." with *Go to your journal*; other errors use `LoadError`; loading uses `ListLoading`; an emptied week redirects (`:64`).
   - `WeekView` (`:68`): header, the Phase 4 slot comment (`:96`), the stats `<dl>`, thumbnails, tag chips (links to `/entries?tag=…`, labelled "Grampians, 4 entries"), the bars, the actions, and `RenameWeek`.
   - `EntryBar` (`:223`) and `SealedBar` (`:261`): each a link to `/entries/:id` with a full `aria-label`; the sealed one reads only `entryDate` and `unlockDate` (its `Pick<>` type says so).

6. **`frontend/src/test/msw/week.ts`**: the mockup's Grampians week with a sealed Loot Drop, a template-prompt entry, a diary-page-only entry and a voice-note-only entry.

## 8. What went wrong
1. The sealed test asserted `queryByRole('img')` was null and found the shell's moon (`role="img"`, "Full moon"). Fixed by checking `document.querySelector('img')` instead, which is what "no photo" means.
2. `tsc -b` failed on the fixture: `TS2352` casting `doc(...)` (typed `Record<string, never> | null`) to `{ content: unknown[] }`. Fixed by writing the paragraph node directly.
3. The first dark screenshot caught the second thumbnail before it loaded (it is lazy). The script now waits for every image to finish before the shot.
4. The design check's `images` line fails, as predicted from the audit's 2x rule and Q29's default. Not fixed: see section 4 and the needs-attention note.
5. An earlier attempt at this task (the run asked "are you stuck") left nothing behind: no notes, no changes, so this run started fresh.
6. **Review blocker: a cached week went stale after an entry write.** `['memoirist','weeks',id]` was refreshed only by the week's own rename and close, and the staleTime is 30 minutes. Open a week, seal or delete one of its entries, go Back: the page drew the sealed entry whole (title, thumbnail, counts; D-10) or the deleted one (D-30). Fixed: `queryKeys.weeks()` is a prefix with `week(id)` under it (`queryKeys.ts:35-36`), and every write that invalidates the feed now invalidates `weeks()` too: `afterSeal` (used by `useSeal` and capture's seal), `useDeleteEntry`, capture's plain save (so Go there shows the new entry) and `useUnlockWatch` (an opened Loot Drop's bar gets its title). Two tests in `WeekSummary.test.tsx` (`entry writes refresh a cached week`) load the week, leave it, seal or delete `e-halls` through the real hook, come back and assert the bar is `Fri 23Loot DropOpens 2 Mar 2027` with the stats at 4 entries, or that 5 bars remain. Taking the `weeks()` invalidation out of `lootDrops.ts` turned both red; restored. Later entry edit, restore and erase tasks must do the same.
8. **Review 2 blocker: invalidating was not enough.** `invalidateQueries` refetches only the queries a page is watching (`refetchType: 'active'`). A week page off screen was only marked stale, so Back drew the cached copy, with the newly sealed entry whole, until the refetch landed. The item-6 tests missed it because they waited (`waitFor`) for the refetched data. Fixed: `dropAndRefetch` in `frontend/src/api/lootDrops.ts` removes the copies no page is watching (`removeQueries({ queryKey, type: 'inactive' })`) and then invalidates, so Back shows the loading state and then the server's answer, while a page on screen keeps its data and refetches. `afterSeal` and `useDeleteEntry` use it for the feed and the weeks (the feed had the same flash; that code is older than this task). Both cache tests now check, straight after `router.navigate` and before any `waitFor`, that "Halls Gap, finally" is not on the page. With the `removeQueries` line taken out, the runs went red: once the seal test (`1 failed | 12 passed`), once the delete test ("expected <span …> to be null", "Halls Gap, finally" received). Which one fails depends on whether the mock refetch lands before the first check, so the red is timing-dependent; with the fix both pass on every run. Restored.

## 10. Concepts to learn from this task
- **Flattening a tree, then scanning it** (`displayTitle.ts:31`, `:65`): `flatMap` with a recursive function turns nested blocks into a flat list of lines; the decision ("first non-heading, else first heading") is then a plain loop. Mixing the walk and the decision is where the server's version needed a mutable builder.
- **`??=`** (`displayTitle.ts:73`): assigns only when the left side is `null` or `undefined`, so "remember the first heading" is one line. `||=` would also replace an empty string.
- **Code points vs UTF-16 units** (`displayTitle.ts`, `cut`): `'😀'.length` is 2; `Array.from(text)` splits by code point, so a cut never leaves half an emoji (Java's `offsetByCodePoints` does the same on the server).
- **Filter first, then aggregate** (`summary.ts:38`): drop what must never be counted before any counting. A `Map` keyed by id counts in one pass; `b.count - a.count || a.name.localeCompare(b.name)` is a two-key sort.
- **`setQueryData` from a mutation's answer** (`weeks.ts:31`): when the server returns the whole new resource, write it into its cache key instead of refetching it, and invalidate only the other views that show it.
- **`<Navigate replace>`** (`WeekSummaryPage.tsx:64`): a redirect while rendering; `replace` swaps the history entry so Back doesn't return to a page that redirects again.
- **`<dl>` for a stats row** (the `<dl>` at `WeekSummaryPage.tsx:101`, `Stat` at `:187`): a figure and its label are a term and a value; `flex-col-reverse` draws the figure on top while the DOM reads "entries 5".

## 12. At work
- A bank statement screen is this page: a period header, totals, then one row per transaction. The "filter first" rule is the one for restricted or reversed transactions: they must never reach a total, even if an upstream service forgets to hide them, and a reviewer looks for that filter next to the sum, with a test that feeds the bad record.
- Two implementations of one rule (server and client display titles) are common when a list endpoint and a detail endpoint differ. The usual guard is shared test cases, or moving the field onto the detail DTO; a reviewer asks which one is the source of truth.
- For an AI agent's UI, `previewLine` is the same job as naming a conversation from its first user line while skipping system prompts.
