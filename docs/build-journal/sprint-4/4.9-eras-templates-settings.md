## 10. Concepts to learn from this task
- **`useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot)`.** React's hook for state that lives outside React. `subscribe(onChange)` returns the function that unsubscribes. `getSnapshot` must return the same value while nothing has changed. Here the value is a string, so that holds.
- **Active and inactive queries.** `invalidateQueries` marks every matching query stale and refetches only those with a mounted observer. The rest refetch when they are next used.
- **Focus return without a trigger.** Radix returns focus to its `Trigger`. A dialog opened from state needs `onCloseAutoFocus` and an element to return to. Radix also runs it when the dialog unmounts.
- **`has-checked:` and `has-focus-visible:`** (Tailwind v4 `:has()` variants) style a label from the hidden radio inside it.
- **`Intl.supportedValuesOf('timeZone')`**: the browser's own IANA list.
- **Calendar months with `differenceInMonths`**: on UTC-midnight dates, so a daylight-saving hour can't move a boundary.
- **A filter that matches the rule's wording.** "Listed when it has a count" reuses a query that already applies the seal, instead of a second copy of the seal clause.

## 12. At work
- **Filtering by the rule you already enforce.** A bank screen that lists "accounts with activity in this period" should reuse the query that already excludes closed, restricted or other customers' rows, not add a second filter that has to repeat those rules.
- **Settings that are device-local and settings that are account-wide** are different things: a theme is per device, a timezone is per user. Mixing them gives surprising results on a second device.
- **Full-replace updates (PUT)** fail quietly when a form doesn't edit every field. The test that checks the whole body (soundtrack included) is what catches it, the same as for a payment instruction amended through a form.
- **An agent's UI** (your AI agent) often needs a hook on state outside React, such as a streaming connection or a cross-tab session. `useSyncExternalStore` is the safe bridge.

<summary>Answers</summary>

1. The count query already applies the three rules (dates, not sealed, not in Recently deleted) and the user scope. "Listed when counted" is one line and can't drift from them. A second SQL filter would repeat the seal clause, which is the mistake CLAUDE.md warns about.
2. No. The week has nothing to show, so it is left out, and the response says nothing about it (D-10). Nothing is stored, so the next read after the unlock instant lists it with a count of 1.
3. The test prefetched the feed with no mounted component, so the query is inactive. `invalidateQueries` marks it stale (`isInvalidated: true`), and it refetches when the Journal mounts it.
4. The inline script in `index.html`, before React loads, so there is no flash of the wrong theme; and `lib/appearance.ts`, after. The script runs before any module, so it can't import the hook.
5. PUT is a full replace (D-26): an omitted soundtrack is cleared. The form must send back what it doesn't edit.
6. "1 month": the range includes both days, so it is measured to 1 March, which is one whole calendar month. Dividing days by 30 would say 28 days.
7. The save refetched the Era, so `updatedAt` changed while the dialog was closing. The dialog was rebuilt and remembered the Save button (then removed) as its opener, so focus fell to the body.
