## 4. Decisions and alternatives
| Decision | Options considered | Chosen | Why | Trade-off accepted |
|---|---|---|---|---|
| How a failed call reaches the UI | Return `{ data, error }` to components (openapi-fetch's own style); throw the raw body; throw a typed `ApiProblem` | **`unwrap()` throws an `ApiProblem`** | TanStack Query treats a thrown error as the query's `error` state, so `isError`, retries and error boundaries all work. One class means a screen reads `error.kind`, never a body | Every query function has to remember `unwrap()`. frontend.md now says so |
| What `kind` holds | The full URN; the HTTP status; the suffix as a string union | **A union of the 13 suffixes plus `network` and `unknown`** | A `switch` on it is checked by TypeScript, and `Record<ProblemKind, string>` makes a missing message a compile error | A new server suffix is `unknown` until it's added here |
| A body that isn't our problem | Use its text as the message; ignore it | **`unknown`, with a fixed sentence** | A proxy's HTML or a stack trace must never reach the screen (API_CONTRACT says nothing from the server's insides comes out; the client keeps that promise) | Less detail when debugging; the status is still kept |
| No response at all | Let openapi-fetch's `TypeError` through; catch it in each hook; an `onError` middleware | **Middleware returns `networkProblem()`** | One place, and the hooks see one error type | A cancelled request must be left alone (§8, item 1) |
| Where the dev header is decided | At module load; per request | **Per request, inside `onRequest`** | In a build, `import.meta.env.DEV` is the constant `false`, so Vite drops the branch and the id (checked: 0 matches in `dist/`). Per request also lets a test flip it with `vi.stubEnv` | None worth noting |
| Header value | A `VITE_DEV_USER_ID` variable; a constant | **A constant, the seeded user** | The task needs only the dev user; a variable would add an `.env.example` entry for nothing yet | Testing as another user means editing one line (or a test's own header) |
| `baseUrl` | `''` (relative); `globalThis.location.origin` | **The page's origin** | Node's `Request` in tests can't resolve a relative URL; in the browser it's the same thing | None |
| `fetch` | openapi-fetch's default (captured when the client is created); `(r) => globalThis.fetch(r)` | **Looked up per call** | MSW patches `globalThis.fetch` when the test server starts, after `client.ts` is imported; a captured reference would skip the mocks | One arrow function |
| `staleTime` | 5 minutes; 30 minutes | **30 minutes** | The rules' limit, with refetch on focus, keeps presigned URLs (60 minutes) fresh while avoiding needless refetches of the feed | A tab focused for over an hour without a refocus could still hold old URLs; the feed task (4.4) can add a refetch interval if it shows |
| Retries | TanStack's default (3 retries of anything); none; only network and `5xx`, at most 2 | **Network or `5xx`, at most twice** | A `404` or `409` answers the same way again, and three retries add about 7 seconds before the error appears | A brief `4xx` glitch isn't retried (there is no such thing in this API) |
| Where `useMe` lives | `src/features/settings/`; `src/api/users.ts` | **`src/api/users.ts`** | `useMe` is needed everywhere (timezone, name), not by one feature; the rule lists `src/api` for the client layer | `src/api` will grow a file per resource |
| `queryOptions` | Hook only; `queryOptions()` plus the hook | **Both** | A route loader or a prefetch in 4.3 can reuse `meQuery()` with the same key and type | One more export |

## 8. What went wrong
1. **A cancelled request became a network problem.** The first `onError` returned `networkProblem()` unless `error instanceof DOMException && error.name === 'AbortError'`. The abort test failed: *expected ApiProblem … to not be an instance of ApiProblem*. Cause: the `DOMException` came from Node's `fetch`, while `DOMException` in the test's global scope is jsdom's, a different class from a different realm, so `instanceof` was `false`. Fix: match on the `name` alone (`isAbort`, `client.ts:33`). The same thing can happen in a browser with iframes, so a name check is the safer habit.
2. **An unused type.** `type ProblemBody = components['schemas']['Problem']` was never used; ESLint and `tsc` both failed on it. Replaced by an exported `FieldErrors` derived from the schema and used by `ApiProblem`, which ties the class to the generated type.
3. **Prettier.** After the edits, `prettier --check` flagged `problem.ts`; `prettier --write` fixed it.
4. **Playwright from the scratchpad.** `import { chromium } from '@playwright/test'` failed with `ERR_MODULE_NOT_FOUND`: ES modules resolve packages from the script's own folder, not the working directory. Imported it by its `file://` URL inside `frontend/node_modules`.
5. **A guess in the docs.** The first troubleshooting row in DEVELOPMENT.md said the proxy answers `500` without a backend. Stopping the backend and measuring showed `502`; the row was corrected.
6. **Two messages that named only one cause** (found by the spec review, fixed at close-out). `payload-too-large` said files can be up to 25 MB, but entry text over 200 KB sends the same problem; `entry-sealed` said the Loot Drop is sealed until it opens, but moving a sealed entry's opening date earlier sends it too. Both sentences now cover both causes (`problem.ts:130`, `:135`), with a new `problem.test.ts` case for `payload-too-large`. Re-run: `Tests 73 passed (73)`, lint, typecheck and build clean. No failed attempts. The audits weren't re-run: the starter page shows neither message.

## 10. Concepts to learn from this task
- **openapi-typescript + openapi-fetch** (`client.ts`): the types are generated from the backend's OpenAPI document, and the client is generic over `paths`, so `api.GET('/api/v1/users/me')` knows the response type and a typo in the path is a compile error. The mistake: hand-writing a type "just for now", which drifts on the next backend change.
- **Middleware** (`client.ts:15`, `:27`): openapi-fetch runs `onRequest` before each call and `onError` when no response arrives. Returning an `Error` from `onError` replaces the thrown error; returning nothing keeps the original. Same idea as a Spring `HandlerInterceptor` or an Axios interceptor.
- **Discriminated error class** (`problem.ts:47`): a class that extends `Error` with a `kind` union. `instanceof ApiProblem` narrows `unknown`, then a `switch (problem.kind)` is checked for completeness. Remember `this.name = 'ApiProblem'`, or logs say `Error`.
- **Narrowing `unknown`** (`problem.ts:77`): `isRecord(value): value is Record<string, unknown>` is a type predicate. After it, `typeof body.type === 'string'` narrows each field. A cast (`body as Problem`) would compile and lie.
- **`Record<Union, string>`** (`problem.ts:124`): an object type that must have a key for every member of the union, so adding a `ProblemKind` without a message fails `tsc`.
- **Query keys and prefix matching** (`queryKeys.ts`): TanStack Query matches `invalidateQueries({ queryKey })` element by element from the start, so `['memoirist']` hits every key and `['memoirist','me']` only that one. `as const` keeps the tuple's literal types.
- **`queryOptions`** (`users.ts:12`): bundles `queryKey` and `queryFn` with their types, so `useQuery(meQuery())`, `queryClient.prefetchQuery(meQuery())` and `getQueryData(meQuery().queryKey)` all agree.
- **`staleTime` vs `gcTime`**: stale means "refetch at the next trigger" (mount, focus, reconnect), not "delete". `gcTime` (5 minutes by default) is how long unused data stays in memory.
- **`import.meta.env.DEV`** (`client.ts:16`): Vite replaces it with a literal at build time, so `if (false) …` is removed with everything only it used.
- **Realms and `instanceof`** (§8 item 1): each JavaScript realm (a window, an iframe, Node next to jsdom) has its own built-in classes. Check `name` or use a brand for errors that may cross one.

## 12. At work
- **Generated clients** are how bank teams keep a React app and a Spring service in step: the OpenAPI document is the contract, and CI regenerates the types so a breaking DTO change fails the frontend build. A reviewer looks for hand-written duplicates of generated types and for calls by unstable operation ids.
- **One error mapper** matters more in a regulated system than anywhere: it decides what a customer sees, and it must never show a stack trace, an internal host or someone else's data. A reviewer checks that raw error bodies never reach the screen or the logs, and that every new error code has a message (here the compiler enforces it).
- **Retry policy** is a real production decision: retrying a `4xx` hides bugs and adds load; retrying a non-idempotent `POST` can double a payment. Here only queries retry, and only on network or `5xx`. In an AI agent the same question applies to tool calls: retry a timeout, never a validation error.
- **Dev-only auth shortcuts** (the dev-user header) are fine if the build provably drops them. Checking the production bundle with `grep` is a cheap, convincing review step.

<summary>Answers</summary>

1. TanStack Query only knows a query failed when its function throws. Throwing puts the error in `error`/`isError`, runs the retry policy and reaches error boundaries; returning it would look like a success with odd data.

8. Every query in the cache, because every key starts with `['memoirist']` and keys match by prefix. That's the "reload everything" lever, for example after a sign-in in Phase 2.
