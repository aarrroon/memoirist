## 10. Concepts to learn from this task
- **Infinite queries** (`api/feed.ts`): `useInfiniteQuery` stores `{ pages, pageParams }` under one key. `initialPageParam` is the first page's param; `getNextPageParam(lastPage)` returns the next one or `undefined`, which sets `hasNextPage` false. The usual mistake is deriving the next page from `allPages.length`, which drifts when the server's view changes; another is never returning `undefined`, which makes a sentinel fetch forever.
- **`infiniteQueryOptions`** (`api/feed.ts:23`): like `queryOptions` in 4.2, it keeps the key, function and types together so a prefetch and the hook can't drift.
- **Error states on an infinite query** (`FeedPage.tsx:27`): `isFetchNextPageError` vs `isError`. In v5 a failed `fetchNextPage` sets `status: 'error'` while `data` still holds the pages, so "no data" is the test for a whole-screen error.
- **Pure functions for business rules** (`grouping.ts`): the D-22 rules take the API's types in and return plain objects out, so 14 unit tests run in milliseconds and the components only draw.
- **Date ranges with open ends** (`isInside`): `null` means "runs on". Write each null case as its own early return; comparing ISO strings works because the format is fixed-width and most-significant first.
- **`position: sticky` inside a section** (`WeekSection.tsx:47`): a sticky element sticks within its parent, so each week's line stays up while its own week scrolls, then the next one pushes it away. No JavaScript.
- **IntersectionObserver for infinite scroll** (`FeedPage.tsx:147`): watches the foot; `rootMargin: '100% 0px'` starts loading a screen early. Disconnect in the effect's cleanup, and keep a button for when the observer doesn't exist.
- **Error boundaries** (`WeekSection.tsx:91`): `react-error-boundary` catches a render error in one entry and shows a fallback, so one bad date doesn't blank the feed. They don't catch errors in event handlers or async code.
- **class-variance-authority** (`button.tsx`): a `cva(base, { variants })` call maps a variant name to classes, and `VariantProps` types the prop from it.
- **Reserving space for images** (`FeedEntry.tsx:78`): an `aspect-4/5` box holds the photo's place before it loads, so layout shift stays at 0; `object-cover` crops the photo to it.
- **Defence in depth on redacted data** (`SealedCard.tsx`): the server redacts sealed entries; the client also reads only the one field it needs, and a test proves it.

## 12. At work
- **Paged APIs.** Bank statements, transaction histories and audit logs are paged the same way. The reviewer's questions: does the client stop at the end, does it ask within the server's limit (here 10 of 50), what happens when page 3 fails after pages 1 and 2 are on screen? Keeping the loaded data and retrying only the failed page is what a customer expects of a transaction list.
- **Date-range containment** is everywhere in banking: a product's effective dates inside a campaign, a rate valid from one day with no end, an account's statement period. `null` as "open-ended" and inclusive ends are the classic sources of bugs; write a test for each null case.
- **Never trust redaction alone.** If the server masks a card number, the UI still shouldn't render a field it doesn't need. Reading only `unlockDate` here is the same habit as showing only the last four digits from a field that only holds them.
- **For your AI agent:** a paginated tool result (search results, documents) needs the same "next cursor or nothing" contract, or the agent loops; and an error in one item shouldn't fail the whole answer (the error-boundary idea).
