## 1. The goal
[Task 4.12](../../SPRINT_PLAN.md#sprint-4-react-ui):

- **Done when:** component tests cover a normal and a sealed entry in the list; restoring puts the entry back in its week in the feed; *erase now* asks for confirmation; and an entry deleted from the feed shows up in the list.

The run added a first step: after 4.11 the feed's first JS chunk was 199.42 kB gzip, 0.58 kB under design.md §6's 200 kB limit. Every new screen imported from `router.tsx` would have pushed it over, so the inner screens had to become lazy before this one was built.

Why now: the API side has existed since task 3.11 (D-30), and the route since 4.3 as a placeholder. The Loot Drop page (4.8) could already delete a sealed entry, but nothing could bring it back, and an ordinary entry could not be deleted at all. The You row for Recently deleted showed no count because nothing read `GET /entries/deleted` yet.

## 8. What went wrong
1. **50 tests failed after the switch to lazy routes.** On a cold load of `/eras` the test found no tab bar at all. Reading `_renderMatches` showed why: until the router is initialised, a matched route that is still `lazy` makes it render only the root match, and with no `HydrateFallback` anywhere the root itself renders `null`. Fix: `hydrateFallbackElement` on each lazy child, which makes the router draw the shell and the fallback in the outlet.
2. **Still failing, with "Not here" on the screen.** A debug test rendered `/settings` twice: the first router showed *You*, the second answered `404 No route matches URL "/settings"`. React Router writes the loaded `Component` into the route objects it was given and drops `lazy`, and every test built its router from the same exported array. Fix: `createRoutes()`.
3. **Eight tests read the next screen synchronously** (`getBy` right after a click, or `router.state.location` at once). A lazy navigation commits after its chunk loads. Fixed with `findBy` and `waitFor`; the asserts didn't weaken.
4. **The first measurement flattered the change.** Vite reported the entry chunk at 170 kB, then 162 kB. But Rollup moved shared code (React Query, Radix, the button) into chunks the entry imports and preloads, so the feed still loads them first. ## 10. Concepts to learn from this task
- **Route `lazy` vs `React.lazy`** (`router.tsx:24`): `React.lazy` makes a component suspend while it loads, so something above must catch it with `<Suspense>` and a fallback shows. A data router's `lazy` loads the route's module during the navigation, before it commits, so the old screen stays up. The mistake: forgetting that the *first* load has no old screen, which is what `hydrateFallbackElement` covers.
- **Libraries that mutate what you pass them** (`createRoutes`): React Router updates its route objects in place after a lazy load. Sharing one config object between two instances then breaks the second. A factory that returns fresh objects is the cheap defence; tests are where it shows first, because they make many instances.
- **Measuring a bundle honestly** (section 7): a chunk's own size is not what a page downloads. Follow its static imports (and `modulepreload` links); dynamic `import()` chunks are not part of the first load.
- **Query key families** (`queryKeys.deleted*`): two queries (`list`, `count`) under one prefix, so `invalidateQueries({ queryKey: queryKeys.deleted() })` refreshes both. `removeQueries({ type: 'inactive' })` + `invalidateQueries` (`dropAndRefetch`) is for data that must not be drawn even briefly (a sealed title); plain invalidation is fine where a stale copy is only late (the deleted list).
- **Mutation callbacks: hook level vs call level** (`DeleteEntryDialog.tsx`): `useMutation({ onSuccess })` runs first, and if it returns a promise TanStack awaits it; `mutate(vars, { onSuccess })` runs after that, and only if the component is still mounted. That is why the feed card could vanish before the dialog's own `onSuccess` ran.
- **Focus when the focused thing disappears** (`RecentlyDeletedPage.tsx:58`, `DeleteEntryDialog.tsx:42`): removing a focused button drops focus to `<body>`, and a keyboard user starts again from the top. Move focus to the thing that explains what happened (a notice with `tabIndex={-1}`), after it is drawn (an effect, not a microtask).
- **Label in name** (WCAG 2.5.3): an `aria-label` must start with the visible text, so a voice user who says "click Restore, still sealed" hits the button.
- **"More than" against a schedule** (`erasureDay`): the job erases rows strictly older than the cutoff; when the sweep instant equals the due instant the row survives a day. Off-by-one at a boundary is the classic bug; the exact-16:00 test pins it.
- **CSS `whitespace-nowrap` on a span** (`RecentlyDeletedPage.tsx:248`): keeps "27 Dec" together while the sentence still wraps between words.

1. Until the router has loaded the lazy routes that match the first URL it is uninitialised and in "render fallback" mode. With no `HydrateFallback` on any matched route, `_renderMatches` keeps only the root match and renders the root's fallback, which is `null`, so even the shell is missing. A `hydrateFallbackElement` on the child route moves the fallback down to the outlet, and the shell draws.
2. React Router writes the loaded `Component` into the route objects and removes `lazy`. The second router built from those mutated objects saw a route with neither a component nor `lazy` and matched nothing, so 404. The app makes exactly one router, so it never reused the objects; `createRoutes()` gives each router fresh ones.
3. Due at 22:00 UTC on 26 November. The 16:00 UTC sweep that day is before it, so the next sweep, 16:00 UTC on 27 November, erases it: 03:00 on 28 November in Melbourne. "27 Oct + 30 days" ignores both the sweep time and "more than 30 days".
4. A cached feed or week page that isn't on screen would otherwise be drawn as it was (without the restored entry, or, after a seal, with private content) until the refetch lands, for up to 30 minutes of staleTime; dropping inactive copies forces a fresh read. A stale deleted list is only late, never leaky, and it refetches on mount because it was invalidated.
5. To the notice ("Restored to the week of …"), which has `tabIndex={-1}`. The notice is drawn on the render after `setNotice`; focusing in `onSuccess` (even in a microtask) runs before that render, so there is nothing to focus yet. The effect runs after the notice is in the DOM.
6. The build split shared code into separate chunks that the entry imports statically and preloads (React Query, Radix, the button, the JSX runtime). The feed downloads them on first load too. Entry plus its static imports is 190.5 kB.
7. Label in name: the accessible name must contain, and should start with, the visible text "Restore, still sealed", or a speech-input user saying what they see won't reach it.
8. The dialog closed by vanishing, so `onCloseAutoFocus` never ran; an unmount effect puts focus on `#main` after Radix's own restore lands on `<body>`.
