## 10. Concepts to learn from this task
- **Playwright fixtures** (`e2e/fixtures.ts:38`): a fixture is a function that gets the fixtures it depends on and a `use` callback. Code before `await use(value)` is setup, code after it is teardown, and Playwright runs the teardown even when the test failed. The usual mistake is clean-up at the end of the test body, which a failed assertion skips.
- **`auto: true`** (`e2e/fixtures.ts:66`): fixtures are lazy, created only for tests that name them. `auto` makes one run for every test, which is what a safety net needs.
- **Overriding a built-in fixture** (`e2e/fixtures.ts:26`): redefining `page` wraps Playwright's own; `addInitScript` runs before the page's scripts on every navigation, so the app starts with the right local storage.
- **Wait for the response, not a timeout** (`f03…:43`): `page.waitForResponse(predicate)` is started before the click and awaited after it, so a fast response isn't missed. Starting it after the click is the classic race.
- **Web-first assertions** (`expect(locator).toBeVisible()`, `expect.poll`): they retry until the timeout, so no `sleep`. `expect.poll` (`f03…:59`) retries any function, here an image's `naturalWidth`.
- **Role locators** (`getByRole('alertdialog', { name: 'Seal this Loot Drop?' })`): the test finds things the way a screen reader does, so it also checks the accessible names.
- **`npm ci` versus `npm install`** (`ci.yml:111`): `ci` installs the lock file exactly and refuses a lock that disagrees with `package.json`; `install` may rewrite the lock.
- **Pinning actions to a SHA** (`ci.yml:100`): a tag can be moved to new code; a commit SHA can't.
- **`Error` with `cause`** (`e2e/global-setup.ts`): `new Error(message, { cause })` adds a helpful message and keeps the original error for the stack trace.

## 12. At work
At a bank the same split shows up: fast unit and component tests on every push, and a small set of end-to-end journeys (log in, make a payment, see it in the history) run against a test environment. A reviewer looks for: tests that clean up after themselves (shared test environments fill with junk otherwise), no sleeps, assertions on the server's answer and not only the screen, and test data that can't collide with another run (here a unique caption per run). For an AI agent, the same idea is an evaluation run against the real tools with recorded clean-up. In CI, a reviewer checks that actions are pinned, the token is read-only, and the install is reproducible (`npm ci`).
