## 8. What went wrong
1. **TypeScript 7.** `create-vite` 9.3.4 now ships TypeScript `~7.0.2` and oxlint. Checking peer ranges before installing showed typescript-eslint (`<6.1.0`) and openapi-typescript (`^5.x`) would refuse it. Pinned 5.9.3, and added `"strict": true`: the template's tsconfig relies on TypeScript 7 turning it on by default, which 5.9 doesn't.
2. **MSW 3 renamed an option.** `onUnhandledRequest` is now `onUnhandledFrame` (it covers WebSocket frames too). Found by reading `node_modules/msw/lib/_chunks/shared-options.d.ts` before writing the setup.
3. **`?raw` gave an empty string.** The token test threw *index.css has no block matching /^:root\s*\{/m*. A failing assertion that printed the import showed `"" LEN 0`. Vitest swaps every CSS import for an empty string unless `test.css.include` matches the file, and that includes `?raw`. Fix: `css: { include: [/src\/index\.css/] }`.
4. **Prettier rewrapped `eslint.config.js`.** The first `npm run lint` failed only at `prettier --check`; `prettier --write` fixed it.
5. **The live theme switch couldn't be shown in the pane.** Emulating light in the browser pane changed `matchMedia(...).matches` but fired no `change` event, even to a listener held on `window`. `tabs_context` showed the pane was hidden: hidden tabs skip the rendering step where media-query events fire. A reload in light gave `data-theme="light"`, `#FFFFFF` and `#111111`. The live switch remains unverified by eye.
6. **The look was decided mid-task.** While 4.1 was being built, commit c355d47 added D-41 and `docs/design/DESIGN.md`, which superseded the round 3 values and `danger` (#B3261E / #F28B82, chosen here from contrast measurements). The tokens were rewritten from DESIGN.md §1–3:
   - `danger` became #B42318 / #F97066.
   - `band`, `on-band`, `on-band-2`, `moon-lit` and `moon-dark` were added.
   - The title sizes gained weight 500 and their letter spacing.

   The token test gained the two `band` pairs, and all checks were run again (36 tests, both audits).
7. **Fonts are still open.** DESIGN.md §2 asks for three woff2 files (Instrument Sans 400 and 600, Newsreader 500), and says the task adding them confirms with the user where they come from. Two ways:
   - `@fontsource` packages: a new dependency.
   - Files downloaded from Google Fonts and committed: a download.

   Neither was done without asking. The tokens name system faces until then.

## 10. Concepts to learn from this task
- **CSS-first Tailwind (`@theme`)** (`src/index.css`): theme variables create utilities. `--color-page` makes `bg-page`. `--color-*: initial` deletes a whole namespace, so a default can't sneak back in. The usual mistake is adding tokens without the reset, which leaves 240 default colours one typo away.
- **`@theme` vs `@theme inline`**: plain `@theme` emits the variable and utilities point at it. `inline` writes the value into the utility, and here the value is `var(--page)`, which changes with `data-theme`. Mapping `--color-page: var(--page)` in plain `@theme` would resolve too early and stop dark mode from working.
- **Text sub-keys** (`--text-heading--font-weight`): one class sets size, line height, weight and letter spacing together, so a heading can't get the size without the weight.
- **Project references** (`tsconfig.json` → `tsconfig.app.json` and `tsconfig.node.json`): browser code and the Node config get different `lib` and `types`, so `process` doesn't type-check in a component. `tsc -b` builds both.
- **Type-aware ESLint** (`projectService: true`): the linter asks TypeScript for types, which enables rules such as `no-floating-promises`. Without it, those rules can't run.
- **MSW's unhandled-request policy** (`src/test/setup.ts`): `'error'` turns a forgotten mock into a failing test instead of a slow, flaky call to a real host.
- **WCAG relative luminance** (`src/tokens.test.ts`): sRGB channels are linearised before weighting, because perceived brightness isn't linear in the stored value. The weights (0.2126, 0.7152, 0.0722) say green dominates.
- **Convention tests** (`src/tokens.test.ts`): like the backend's `EntryMapperIsTheOnlyPathTest`, they test the shape of the code, not its behaviour. They are cheap, and they catch the slip a reviewer misses.

## 12. At work
- **The scaffold** is what a platform team hands every new front end: pinned versions, one lint command that includes formatting, and tests that can't reach the network. A reviewer checks the lockfile is committed, the ranges are exact, and `strict` is really on. A template upgrade can silently change compiler defaults, as TypeScript 7 did here.
- **Design tokens with the framework's defaults removed** are how a design system survives many contributors. The check-in that matters is the reset line; without it, review is the only guard.
- **Peer-range checks before an upgrade** (`npm view <pkg> peerDependencies`) save a broken install. On a large repo, the same question decides whether a TypeScript or ESLint major can land yet.

<details>
<summary>Answers</summary>

1. typescript-eslint 8.74 accepts `>=4.8.4 <6.1.0`, and openapi-typescript 7.13 needs `^5.x`. TypeScript 7 is outside both, so npm would refuse the install or the tools would break.
2. Plain `@theme` emits `--color-page: var(--page)` on `:root`, and the variable resolves there, where `--page` is the light value. Elements inside `[data-theme=dark]` would inherit the already-resolved light colour, so dark mode would stop working. `inline` puts `var(--page)` into each utility, where it resolves on the element itself.
3. Spacing utilities are generated from the `--spacing` multiplier (4 px × n), not from named tokens, so any number works, and widths and heights need that freedom. The design check (`audit.mjs`) measures every padding and gap and fails anything off the 4/8/12/16/24/32/48/64 scale.
4. *dark mode declares every token light mode does* fails with a list diff showing `--success` missing on the dark side. *every mode token is a Tailwind utility* fails with `['--success']`.
5. `main.tsx` is a module script, so it is deferred and runs after the HTML is parsed. An inline script in `<head>` runs before the first paint, so a dark phone never flashes the light page.
6. Vitest replaces CSS imports with `""` unless `test.css.include` lists the file, `?raw` included. Reading with `fs` would need Node's types in `tsconfig.app.json`, which would let browser code type-check calls to `process` or `Buffer`.
7. A test that forgets a mock would otherwise send a real request: slow, flaky, and possibly to a real server. With `'error'`, that request fails the test. MSW 2 called the option `onUnhandledRequest`.
8. Prettier keeps each file's existing line endings, so a CRLF checkout on Windows and an LF checkout in CI both pass `prettier --check`. With `lf`, Windows checkouts would fail unless `.gitattributes` forced `eol=lf` for `frontend/`.

</details>
