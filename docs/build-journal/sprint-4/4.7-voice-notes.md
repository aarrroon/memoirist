## 3. The plan
1. Pure helpers first (`lib/recording.ts`): choosing the format, naming the file, folding loudness samples into 32 bars. No browser needed, so plain unit tests.
2. The length problem (`lib/audioDuration.ts`): Chrome's WebM recordings report `duration === Infinity`. A helper that finds the real length, testable with a fake `EventTarget`.
3. The player (`components/VoiceNote.tsx`), shared by the feed and capture: play/pause plus a slider.
4. The recorder hook (`useRecorder.ts`) with its state machine, then the UI that shows it (`VoiceRecorder.tsx`).
5. Wire it into capture: the Voice button, the tray's voice rows, the recording joining `items` so 4.6's `saveEntry` uploads it unchanged.
6. Real Chromium with a fake microphone: record, save, play back from the feed; then the design audits and the screenshots.

That order goes from the parts that can be proven without a browser to the parts that can't, so the hard-to-test glue is small.

## 8. What went wrong
1. **`erasableSyntaxOnly`.** `tsc -b` failed with `TS1294: This syntax is not allowed when 'erasableSyntaxOnly' is enabled` on the fake audio class in the test. Constructor parameter properties (`constructor(private readonly onLoad…)`) generate JavaScript, so the project's TypeScript setting forbids them. Fix: plain fields assigned in the constructor.
2. **A 4.5 test timed out.** `FeedEntry.test.tsx`'s keyboard test pressed Enter and waited for "Pause voice note", but Play now awaits `readDuration`, which waited 5 s for a `loadedmetadata` that jsdom never fires. Fix: `test/setup.ts` makes `load()` fire `loadedmetadata`, and `readDuration` returns null at once for `NaN` (only `Infinity` is the WebM case), which is also right in a real browser.
3. **Test queries.** "Found multiple elements with the role status" (the draft line is a live region too): asserted on the text instead. Adding 20 photos was slow without the `browser-image-compression` mock that `CaptureView.test.tsx` uses: added the same mock.
4. **Lint.** `react-hooks/immutability`: the hook's callback used `addRecording` before it was declared. Fixed with a ref set in an effect. `no-useless-assignment` on `let context = null` that every path overwrote.
5. **Docker Desktop had crashed** after the machine restarted: `bootRun` failed with "Connection to localhost:5432 refused". Starting Docker Desktop crashed again: its log said `initializing Secrets Engine: … rename …/docker-secrets-engine/engine.sock …engine.sock.stale: The file cannot be accessed by the system`. The socket file was broken (`ls` showed `-?????????`) and `del` couldn't remove it. Fix: ended the crashed Docker processes, renamed the folder `%LOCALAPPDATA%\docker-secrets-engine` to `docker-secrets-engine.broken-20261125` (nothing deleted, so it can be put back), started Docker Desktop (`Server Version: 29.9.2`), `docker compose up -d`.
6. **A real Chrome bug the unit tests didn't catch**, then a false alarm. The Playwright run showed the feed's note still playing after Enter should have paused it. ## 10. Concepts to learn from this task
- **MediaRecorder** (`useRecorder.ts:139`): records a `MediaStream` into compressed chunks. `MediaRecorder.isTypeSupported` is the only honest way to know a browser's formats; user-agent sniffing guesses. `start(1000)` delivers a chunk every second through `ondataavailable`; `stop()` delivers the last one, then `onstop`. The mistake: building the file before `onstop`, which loses the last chunk.
- **getUserMedia and its errors** (`useRecorder.ts:68`): it rejects with a `DOMException` whose `name` says why: `NotAllowedError` (refused), `NotFoundError` (no microphone). Stopping every track (`track.stop()`) is what turns off the browser's recording light; forgetting it is the classic leak.
- **AnalyserNode** (`useRecorder.ts:149`): Web Audio's tap on a stream. `getByteTimeDomainData` fills bytes centred on 128; the root mean square of `(b - 128) / 128` is the loudness.
- **A promise from events, with a timeout** (`audioDuration.ts:27`): one `finish` function that clears the timer, removes every listener and resolves. A promise settles once, but listeners stay attached until removed.
- **Discriminated union + `useReducer`** (`useRecorder.ts:22`, `:45`): the `status` field narrows the type, so `state.reason` only exists on `failed` (TypeScript refused `state.reason` on `denied` while building `VoiceRecorder.tsx`). The reducer returns the same object for an action that doesn't fit, which also tells React nothing changed.
- **A custom ARIA slider** (`VoiceNote.tsx:104`): `role="slider"` with `aria-valuemin`, `-max`, `-now` and a readable `aria-valuetext`, `tabIndex={0}`, and keys handled in `onKeyDown` with `preventDefault` so the arrows don't scroll the page.
- **The "latest callback" ref** (`CaptureForm.tsx:133`, `useRecorder.ts:93`): a ref updated in an effect lets a long-lived callback (the recorder's `onstop`) call the newest function without restarting anything.
- **`erasableSyntaxOnly`**: TypeScript 5.8's flag that bans syntax which emits code (enums, parameter properties, namespaces), so the code runs under type stripping as written.

## 12. At work
- **State machines for flows that can be interrupted.** A payment, a KYC upload or an agent's multi-step tool run has the same shape as the recorder: asking, in progress, refused, failed, cancelled, and a late answer arriving after a cancel. A reviewer looks for booleans that can contradict each other and for the late reply that resurrects a cancelled flow; a union plus a reducer makes both visible.
- **Timeouts with cleanup.** Every wait on something outside your control (a browser event, a webhook, an LLM call) needs a timeout, and the cleanup must run on every path. `nextEvent` is the small version of `Promise.race` with an `AbortController`.
- **Feature detection over browser sniffing.** Banks support old Safari on iPhones for years; `isTypeSupported`, hiding a feature that can't work and saying why (F-03) is the accessible, testable way.
- **Releasing resources.** The microphone light is the user-visible version of a leaked connection or file handle; a reviewer checks that every acquire has a release on success, failure and cancel.

3. The user presses Voice, then Discard while the browser's microphone prompt is still open, then allows the microphone. What does the code do, and which two pieces make sure of it?
4. Why are voice notes kept after the pictures in the order sent to the server?
5. Why is the Stop button outlined rather than filled with the accent?
6. Why does the feed's player draw a line, not bars, for a voice note it didn't record?
7. Which error name from `getUserMedia` means the user refused, and what does F-03 require the screen to say?
8. How would you test the MP4 path without a Mac?

<details><summary>Answers</summary>

1. Chrome's `MediaRecorder` writes WebM as a stream and never goes back to write the duration in the header, so `duration` is `Infinity`. `readDuration` seeks far past the end, which makes the browser read to the end and fire `durationchange` with the real length, then seeks back to 0 and waits for `seeked` before playing.
2. Each Play on each note would leave listeners on its `<audio>` element. They'd keep the closures alive (a memory leak) and, on a later `durationchange`, call `finish` again, which is harmless for the settled promise but runs cleanup code twice.
3. Discard bumps `attempt.current` and dispatches `finished` (idle). When `getUserMedia` resolves, `mine !== attempt.current`, so the hook stops the stream's tracks at once and returns. Even if a `started` were dispatched, the reducer ignores it from idle.
4. The swipe shows pictures only, and lists name an entry by its first media item (D-24, `firstMediaKind`). A voice note first would make a photo entry read "Voice note".
5. Save is the screen's one filled primary button (design.md §8). The accent still marks Stop as the action (§7), through its border and icon.
6. Nothing stores a recording's levels on the server, and decoding every note in the feed would fetch every file. Bars that aren't measured would show a recording that isn't there.
7. `NotAllowedError` (or `SecurityError`). F-03: a message explaining how to allow the microphone, and that photos still work.
8. Make `MediaRecorder.isTypeSupported` return true only for `audio/mp4` with a fake recorder (as `VoiceRecorder.test.tsx` does), and check the upload's type and file name. A real Safari check still needs a Mac or iPhone, or Playwright's WebKit, which isn't installed here.
