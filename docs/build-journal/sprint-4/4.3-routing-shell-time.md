## 4. Decisions and alternatives
| Decision | Options considered | Chosen | Why | Trade-off accepted |
|---|---|---|---|---|
| How "today" is worked out in a zone | `Date#getDate()` (the browser's zone); `toLocaleString('en-AU', { timeZone })` then parse; adding a fixed offset; `TZDate` from `@date-fns/tz` | **`new TZDate(instant, zone)`, then date-fns** | `TZDate` is a `Date` whose getters answer in its zone, and `format()` respects it. Daylight saving comes from the browser's IANA data, so no offset is ever written down. Parsing `toLocaleString` output is fragile and locale-dependent | Every caller must pass the zone; that's the point |
| Shape of the time API | A hook that reads the zone itself (`useToday()`); pure functions taking `(instant, zone)` | **Pure functions with explicit `now` and `zone`** | Plain unit tests with fixed instants, no React, no fake timers; the zone comes from `useMe()` in the component. Mirrors the backend's injected `Clock` | Callers write `todayIn(zone, now)` instead of `useToday()` |
| A calendar day ("2026-10-26") | `parseISO` (local midnight in the browser's zone); hold it at midnight UTC and format in UTC | **Midnight UTC via `TZDate(y, m, d, 'UTC')`** | A calendar day has no zone. Parsing it in the browser's zone and formatting it there happens to work, but only by luck; holding it in UTC is the same everywhere, and a test changes the machine's zone to prove it | A malformed string throws `RangeError` instead of becoming *Invalid Date* |
| Which nav item is current | `NavLink`'s own `isActive`; matching `location.pathname` in the shell; a `handle` on each route read with `useMatches()` | **Route `handle` + `shellFor()`** | `NavLink` marks `/` active only on `/`, but the week summary belongs to Journal and Templates to You on a phone. A table of path prefixes in the shell would duplicate the route table. With `handle`, each route says where it sits, in one place (`router.tsx`), checked by `satisfies ShellHandle` | React Router types `handle` as `unknown`, so the shell needs a type guard |
| The moon | A static SVG in `src/assets/` like the Loot Drop star; a set of eight SVG files; computed in a component | **Computed outline (`lib/moon.ts`) drawn by `Moon.tsx` in the moon tokens** | Its shape changes every day; eight files would show a quarter moon for three days. design.md §5's "never improvise a drawing in JSX" is about the Loot Drop object. An assumption for the user | A small amount of geometry to test (§6) |
| The Write menu | A Vaul sheet; a hand-rolled popover; shadcn/ui's dropdown on Radix | **shadcn/ui `DropdownMenu`, copied into `components/ui/` and rewritten to the tokens** | DESIGN.md §8 calls it a menu button; Radix gives the whole WAI-ARIA pattern (arrows, Enter/Space, Escape, focus back to the button, typeahead). | What choosing a menu item does now | Open a placeholder dialog; navigate to a placeholder route; set UI state only | **`openCapture(kind)` in the Zustand store** | 4.6 builds the sheet and only has to read `capture`. A placeholder dialog would invent a look DESIGN.md gives for the real sheet | Tapping *New entry* shows nothing until 4.6 |
| Zustand store shape | One store per concern; one UI store | **One `useUiStore` with `capture`, `openCapture`, `closeCapture`** | The task asks for "a Zustand UI store"; later UI state (the selected Era, the draft's open state) can join it | It will grow; slices can be split later |

Following a fragment only moves the caret, not focus (found by the Playwright run, §8) | `<main>` has `tabIndex={-1}` and `outline-none` |

## 8. What went wrong
1. **A test that navigated outside `act()`.** *You leads to Tags, Templates and Recently deleted* called `await router.navigate('/settings')` and then looked for the *Templates* row: `Unable to find an accessible element with the role "link" and name "Templates"`; the page still showed Tags. The router's state changed, but React hadn't rendered it. Fix: `await act(() => router.navigate('/settings'))`, then query `main` again.
2. **`Not implemented: Window's scrollTo() method`**, dozens of times. `<ScrollRestoration />` scrolls to the top on every navigation, and jsdom has no layout. Fix: `window.scrollTo = () => undefined` in `src/test/setup.ts`.
3. **`process` isn't typed in the app.** The machine-zone test set `process.env.TZ`; ESLint failed with *Unsafe member access .env on a type that cannot be resolved* and `tsc` with *Cannot find name 'process'* (the app's tsconfig has browser types only, rightly). Fix: `vi.stubEnv('TZ', …)` and `vi.unstubAllEnvs()` in `afterEach`. Node switches its zone as soon as `TZ` is assigned, so a plain `Date` really does change mid-test (the test asserts it).
4. **Prettier** reformatted 11 new files (long prop types, the route table). `prettier --write src`.
5. **A grey 3 px focus ring under reduced motion.** The Playwright script read `outline=solid 3px rgb(17, 17, 17)` on every focused link, where the token says 2 px accent. A probe without `reducedMotion` showed `solid 2px rgb(143, 102, 20)`. Bisecting the context options pointed at `reducedMotion: 'reduce'` alone. Cause: 4.1's reduced-motion rule sets `transition-duration: 0.01ms !important` on everything, and `transition-property` defaults to `all`, so with it every property change, the outline included, becomes a 0.01 ms transition; read in the same tick as the focus, the computed style is still the starting value. Nobody can see 0.01 ms, so `index.css` was left alone; the script waits 50 ms before reading. Worth knowing for any test that reads computed styles under reduced motion.
6. ***Skip to content* left focus on `<body>`.** Two causes. The page: following `href="#main"` moves the sequential-focus starting point and scrolls, but doesn't focus the target. Fix: an `onClick` that calls `focus()` on `#main` (`AppShell.tsx`), and the component test now asserts `main` has focus. The script: it pressed Tab before React had rendered; it now waits for the greeting first.
7. **Two moon lines.** On the You screen the script waited for the greeting text and found the side nav's copy first, which is `display: none` on a phone: `locator resolved to hidden <span>Tuesday at night`. Scoped it to `header`.
8. **The bundle doubled.** 4.2's build was 82.52 kB gzipped; this one is 163.80 kB. A sourcemap estimate (unminified sources): React Router 374 KB, tailwind-merge 108 KB, date-fns 97 KB, Radix's menu with `@floating-ui` about 120 KB. It's under design.md §6's 200 KB for the feed's first JavaScript, but most of the room is gone before the feed exists. Not fixed here (no change helps without a measured choice); flagged for 4.4, where lazy routes (`React.lazy` per screen) and lazy capture are the obvious levers.
9. **The top bar was off the gutter on a tablet** (found by the spec review). From `md` to `lg`, `<main>` is a centred 640 px column, but the top bar's content used the full width with `md:px-6`, so the back link and moon line started 24 px from the edge while the screen started about 88 px in. audit.mjs measures only 375 and 1440 px, so it never saw it. Fix (close-out): `TopBar.tsx` keeps the full-width background and puts its content in the same `mx-auto w-full max-w-160 px-4 md:px-6` column as `<main>`. A Playwright probe measured the top bar's content and the screen's content starting at the same x: 16 px at 375, 88 px at 768, 215.5 px at 1023, with no sideways scroll. audit.mjs on `/weeks/<id>` and `/settings`, light and dark: *No check failed.* `npm test` (131 passed), lint, typecheck and build pass. No failed attempts.

## 10. Concepts to learn from this task
- **An instant versus a calendar day** (`time.ts:19`, `:47`): an instant (`2026-10-04T13:30:00Z`) is the same moment everywhere and becomes a *day* only in a zone; a calendar day (`entryDate`) has no zone at all. Most date bugs come from treating one as the other, for example parsing `"2026-10-26"` with `new Date()`, which is UTC midnight, then reading it in Melbourne.
- **`TZDate`** (`time.ts:20`): a `Date` subclass from `@date-fns/tz` whose `getHours()`, `getDate()` and date-fns' `format()` answer in its own zone. The mistake: `new Date(...).getHours()`, which answers in the machine's zone.
- **Daylight saving as data, not arithmetic** (`time.test.ts`): never add `+10`; ask the IANA database (through `Intl`, which `TZDate` uses) what the offset was at that instant. The October test is the proof.
- **Testing against the machine's zone** (`vi.stubEnv('TZ', …)`): a test suite that runs in Melbourne can't catch "used the browser's zone" with Melbourne data. Changing `TZ` mid-test does.
- **React Router data mode** (`router.tsx:18`, `main.tsx`): routes are plain objects made once outside React (`createBrowserRouter`), rendered by `<RouterProvider>`. A layout route's `Component` renders `<Outlet />` where the child goes. `createMemoryRouter` takes the same table in tests.
- **Route `handle` + `useMatches()`** (`router.tsx`, `places.ts:41`): any data you attach to a route, readable by every component through the matched chain. Breadcrumbs and page titles are the textbook uses.
- **`satisfies`** (`router.tsx`): checks a value against a type without changing the value's own inferred type, so `{ place: 'journal' } satisfies ShellHandle` fails to compile on a typo but the route stays a plain `RouteObject`.
- **User-defined type guards** (`places.ts:31`): `handle is ShellHandle` teaches the compiler what a runtime check proved, so `unknown` narrows without a cast.
- **Zustand's curried `create<T>()(…)`** (`ui.ts:19`) and selectors (`useUiStore((s) => s.openCapture)`): the extra `()` lets you name the state type while the rest is inferred; a selector re-renders a component only when its slice changes.
- **The menu-button pattern** (`WriteMenu.tsx`, Radix): `aria-haspopup="menu"`, arrow keys between items, Escape returns focus to the button. Writing it by hand is where most custom dropdowns fail accessibility review.
- **React 19 `<title>`** (`Page.tsx`): rendered anywhere, it's hoisted into `<head>`; no `react-helmet`.
- **`aria-current="page"` as a style hook** (`TabBar.tsx`): Tailwind's `aria-[current=page]:` variant styles the current tab from the same attribute screen readers announce, so the look and the semantics can't disagree.

## 12. At work
- **Business dates and cut-offs.** A bank lives on "which day is it?": a payment's value date, the end-of-day batch, a statement period, a transfer made at 11:30 pm in Perth to an account in Sydney. The same rule applies: store instants in UTC, store calendar days as dates, and turn one into the other only with a named zone (Java's `ZonedDateTime` / `LocalDate.now(clock.withZone(zone))`, the same pattern as this backend). A reviewer looks for `new Date().getDate()`, `LocalDate.now()` without a clock or zone, and offsets written as numbers.
- **Test the zone you aren't in.** CI servers usually run in UTC and laptops in Sydney; a test that passes on both can still be wrong for Perth. `TZ=…` in a test (or `-Duser.timezone` in Java) is cheap insurance.
- **Navigation as configuration.** Enterprise apps grow dozens of screens; deriving the current menu item, breadcrumbs and page titles from route metadata keeps them from drifting apart. In an agent UI the same idea maps a route to the tools or context a screen offers.
- **Accessibility review.** A custom dropdown is the classic failing item in an accessibility audit; using a headless library (Radix) for the pattern and styling it yourself is the usual enterprise answer.
