# Task 4.5: Entry card

> **Sprint:** 4 · **Commit:** `Sprint 4.5: Store photo sizes and build the swipe and caption`, on `phase-1-sprint-4` · **Status:** done (unattended; spec review passed with notes on the second pass) · **Time taken:** roughly 50 minutes of build and checks (03:12 to 04:02 AEDT), plus this entry
> **Built:** photos now store their width and height (a `V2` migration, read from the file's header on upload), and each feed entry shows an Embla swipe whose frame is reserved from the first photo's shape, a caption drawn from its TipTap JSON, and a voice note row.

## 1. The goal
[Task 4.5](../../SPRINT_PLAN.md#sprint-4-react-ui):
- **Do:** backend first: `V2__media_dimensions.sql` adds `media.width` and `media.height` (nullable, both or neither); an upload reads an image's size from its header without decoding it; voice notes and unreadable headers stay `null`; `Media` responses gain `width` and `height`; then `npm run gen:api`. On the screen: an Embla carousel (keyboard-operable) whose height is reserved from the first photo's shape, kept between 4:5 and 1.91:1 (4:5 with no size), with dots below; and a read-only caption rendered from JSON, never through `dangerouslySetInnerHTML`.
- **Done when:** an upload test stores the size of a JPEG, a PNG and a WebP, and `null` for a voice note and an unreadable image; component tests cover image-only, caption-only and mixed entries, and a tall, a wide and a size-less first photo; the feed's layout shift is 0.1 or less.

Why now: 4.4 drew the least version of an entry (first photo in a fixed 4:5 frame, `contentText` as plain text) because photos had no size. The frame can only take a photo's own shape once the server stores it (D-17), so this task starts in the backend. Every later screen that shows photos (the entry view, the week summary, Era covers) reuses the swipe, `frameRatio` and `RichText` built here.

## 4. Decisions and alternatives
| Decision | Options considered | Chosen | Why | Trade-off accepted |
|---|---|---|---|---|
| How to read the size | `ImageIO.getImageReaders` + `getWidth(0)`; a library (metadata-extractor); our own header parser | Our own (`ImageSize`) | The JDK has no WebP reader, so one of three types would always be `null`; a library is a new dependency for ~100 lines of documented headers | We own a parser; its tests use real encoder output (JDK JPEG/PNG, Chromium WebP) to keep it honest |
| Which format to parse as | Trust the declared type; sniff the signature | Sniff | The size is a fact about the bytes; a mislabelled PNG still gets its size. The type check (415) stays on the declared type, unchanged | A voice note is never read at all (checked by type first), so sniffing can't give audio a size |
| The CHECK constraint | `width > 0 AND height > 0`; `(width IS NULL) = (height IS NULL)` plus two range checks; one OR of "both null" and "both set and positive" | The OR form | A NULL CHECK passes, so the first lets `(640, NULL)` in. Proved on a temp table in Postgres: the careless form inserted the row, ours raised `violates check constraint` | One constraint name for three rules, so the error doesn't say which half failed |
| Where the size is read | Inside the write transaction; before storing, outside any transaction | Before storing | The method is deliberately not `@Transactional` (task 3.6); reading a header takes microseconds but needs no lock | The multipart file is opened twice (once for the header, once to store) |
| Seeder sizes | Hard-code 960 × 640; read them with `ImageSize` | `ImageSize.read` | The sample photos go through the same reader as uploads, so a change to `PlaceholderImages` can't drift | None |
| Caption renderer | TipTap's static renderer (not installed); TipTap `EditorContent` read-only (ships the editor in the feed); our own JSON→React | Our own (`RichText`) | design.md §6 keeps the editor out of the feed's bundle; the allow-list fits one `switch` | A new node type needs a case here as well as on the server |
| Headings in a caption | `<h3>`/`<h4>`; `<p>` in body 600 | `<p className="font-strong">` | A caption's heading is a template prompt (D-06); real headings would break the feed's outline (weeks, then entries) | Screen readers can't jump to prompts in the feed; the entry view (4.12) can use headings |
| Re-checking links on screen | Trust the server's validator; check again | Check again (`safeHref`) | An `href` is the one way stored text could run script; a second allow-list costs one function | Two copies of one rule (server and client) |
| The frame's ratio in CSS | `style={{ aspectRatio }}`; `aspect-[1.5]` (arbitrary value); a custom property with `aspect-(--frame)` | Custom property | Data, not a design value (D-40 forbids one-off sizes), and a test can read `--frame` | One more indirection to read |
| Lazy photos after the first | `loading="lazy"` on every slide; render `<img>` only once wanted | Render once wanted (`loadUpTo`) | Chrome's lazy loading looks sideways too, so slide 2 (375 px to the right) would load with slide 1; design.md wants one photo per entry until the user swipes | An empty `--surface` frame shows for a moment on a fast swipe |
| Keyboard selection | Only from Embla's `select` event; set it ourselves too | Both | Dots and alt text agree at once, and in jsdom (no layout, so no `select`) the keys still work | Two sources write `selected`; they agree because both clamp to the same snaps |
| Arrow that reaches the end | Hide it; disable it; hide it and move focus | Hide and move focus to the swipe | DESIGN.md shows arrows only where they work; a hidden focused button drops focus to `<body>` | Focus jumps from the button to the swipe (announced as the carousel) |
| Voice note length | `preload="metadata"`; `preload="none"` | `none` | A feed of voice notes would fetch each file's header on a slow phone; the length shows once played | The length isn't shown until the first play |

## 5. How it was built
**Backend, in review order**
- [`V2__media_dimensions.sql`](../../../backend/src/main/resources/db/migration/V2__media_dimensions.sql): two nullable `INTEGER` columns and `chk_media_dimensions`. The comment says why the CHECK is written with `IS NOT NULL` on both sides.
- [`ImageSize.java`](../../../backend/src/main/java/com/memoirist/media/ImageSize.java): a record (width, height ≥ 1) with `read(InputStream)` at [:43](../../../backend/src/main/java/com/memoirist/media/ImageSize.java#L43). It reads 4 bytes and dispatches on the signature: PNG ([:67](../../../backend/src/main/java/com/memoirist/media/ImageSize.java#L67), the `IHDR` chunk at byte 16), JPEG ([:85](../../../backend/src/main/java/com/memoirist/media/ImageSize.java#L85), walking segments by their lengths until a start-of-frame marker, skipping fill bytes and standalone markers, giving up at `SOS`/`EOI`), WebP ([:134](../../../backend/src/main/java/com/memoirist/media/ImageSize.java#L134), the `VP8X`, `VP8 ` and `VP8L` layouts, with the 14-bit fields of the last two). Any `IOException` (a header cut short is `EOFException`) or a size of 0 (the record's compact constructor throws) becomes `Optional.empty()`.
- [`Media.java`](../../../backend/src/main/java/com/memoirist/media/Media.java): `width`/`height` as `Integer` (`updatable = false`), set from an `ImageSize` in a new 8-argument constructor; the old 7-argument one delegates with `null`, so the six tests that build media didn't change.
- [`MediaResponse.java`](../../../backend/src/main/java/com/memoirist/media/dto/MediaResponse.java): `@Schema(nullable = true) Integer width, height`, which `openapi-typescript` turns into `number | null`. [`MediaMapper`](../../../backend/src/main/java/com/memoirist/media/MediaMapper.java) passes them on.
- [`MediaService.java:129`](../../../backend/src/main/java/com/memoirist/media/MediaService.java#L129) reads the size before the file is stored; [`sizeOf` at :269](../../../backend/src/main/java/com/memoirist/media/MediaService.java#L269) skips non-images and turns any failure into `null`. The size travels into the write transaction's `insert`.
- [`SampleContentSeeder`](../../../backend/src/main/java/com/memoirist/dev/SampleContentSeeder.java) gives the sample photos their size through the same reader.

**Frontend**
- [`lib/photoFrame.ts`](../../../frontend/src/lib/photoFrame.ts): `frameRatio` (practice block): the first photo's width ÷ height clamped to [0.8, 1.91], 0.8 for anything unusable.
- [`lib/links.ts`](../../../frontend/src/lib/links.ts): `safeHref` (practice block), the client copy of the server's link allow-list.
- [`lib/tiptap.ts`](../../../frontend/src/lib/tiptap.ts): `toNode` turns the `unknown` document into checked `DocNode`s, dropping anything that isn't one; `hasText` says whether there is a caption at all.
- [`components/RichText.tsx`](../../../frontend/src/components/RichText.tsx): `withMarks` at [:21](../../../frontend/src/components/RichText.tsx#L21) folds a text run's marks with `reduceRight`, so the first mark is the outermost element, as TipTap stores them; `renderNode` at [:59](../../../frontend/src/components/RichText.tsx#L59) is the one `switch`. `clamp` makes it the feed caption: `line-clamp-3`, blank paragraphs and rules left out.
- [`components/Swipe.tsx`](../../../frontend/src/components/Swipe.tsx): `useEmblaCarousel` at [:47](../../../frontend/src/components/Swipe.tsx#L47) (`active` only with more than one photo); `loadUpTo` at [:54](../../../frontend/src/components/Swipe.tsx#L54) decides which slides render an `<img>`; `go` clamps, warms up the next photo, sets `selected` and scrolls (a jump under reduced motion); `press` at [:105](../../../frontend/src/components/Swipe.tsx#L105) hands focus to the swipe when an arrow reaches the end; `onKeyDown` handles ←, →, Home and End. The frame is `aspect-(--frame)` with the ratio in `--frame`.
- [`components/VoiceNote.tsx`](../../../frontend/src/components/VoiceNote.tsx): a 44 px round button that plays and pauses a hidden `<audio preload="none">`, and the length once known. [`lib/media.ts`](../../../frontend/src/lib/media.ts) holds `isPicture` and `formatLength` (moved out of the component files for React Refresh, see §8).
- [`features/feed/FeedEntry.tsx`](../../../frontend/src/features/feed/FeedEntry.tsx#L78): the swipe for pictures, `RichText` for the caption ([:83](../../../frontend/src/features/feed/FeedEntry.tsx#L83)), a `VoiceNote` row per voice note ([:87](../../../frontend/src/features/feed/FeedEntry.tsx#L87)). A sealed entry still goes to `SealedCard` and never reaches any of these.
- [`test/setup.ts`](../../../frontend/src/test/setup.ts): inert `ResizeObserver`, `IntersectionObserver` and `matchMedia` for Embla in jsdom, and `play`/`pause` that fire their events.

## 10. Concepts to learn from this task
- **A CHECK that is NULL passes** (`V2__media_dimensions.sql`): SQL has three truth values, and a constraint fails only on FALSE. `width > 0 AND height > 0` with `height` NULL is NULL, so the row gets in. Write "both null, or both set and valid" explicitly. Same trap in `WHERE`, but reversed: there NULL drops the row.
- **Reading a binary header** (`ImageSize.java:85`): `DataInputStream.readUnsignedShort()` is big-endian (JPEG, PNG); WebP is little-endian, so it's assembled by hand (`a | b << 8`). `skipNBytes` (Java 12+) throws `EOFException` when the file ends, unlike `skip`, which may silently skip less.
- **A compact constructor** (`ImageSize`): `public ImageSize { if (width < 1 …) throw … }` validates a record's components without repeating the assignments. The mistake is assigning `this.width = …` inside it (not allowed) or forgetting it runs for every construction.
- **`Optional` as "no answer"** (`ImageSize.read`): the method can't fail for a bad file; the caller chooses the fallback (`orElse(null)` at the JPA boundary, where `Integer` columns are nullable).
- **`reduceRight` to wrap** (`RichText.tsx:21`): folding marks from the inside out gives `<strong><em>text</em></strong>` for `[bold, italic]`. With `reduce` the first mark would end up innermost.
- **Parsing `unknown`** (`lib/tiptap.ts`): the generated type for the document is `Record<string, never>`, so it's treated as `unknown` and narrowed with a type guard (`isObject`) field by field, never cast. `.filter((n) => n !== null)` narrows `(T | null)[]` to `T[]` in TypeScript 5.5+.
- **A callback ref** (`Swipe.tsx:98`): Embla gives a ref *setter*; wrapping it in your own callback lets you keep the node too (`viewportNode.current = node; viewport(node)`). `useCallback` keeps it stable, or React calls it with `null` and the node on every render.
- **Roving selection vs focus** (`Swipe.tsx:110`): the swipe is one tab stop; arrow keys change what's shown inside it (`aria-hidden` on the others), the pattern WAI-ARIA describes for a carousel. Home and End come free.
- **`prefers-reduced-motion` in JavaScript**: CSS can't stop a library's scroll animation, so the code asks `matchMedia` at the moment of the press and passes `jump`.
- **A CSS custom property for data** (`aspect-(--frame)`): Tailwind v4's `(--var)` shorthand writes `aspect-ratio: var(--frame)`, so the value comes from the data without an arbitrary class.

## 12. At work
- **Untrusted files at an API boundary.** A bank's document upload (statements, ID scans) needs the same shape: an allow-listed type, a size limit, and anything read from the bytes read defensively, never trusting a header's numbers. A reviewer would ask: what happens with a truncated file, a zero, a huge number, a mislabelled type? And does a parse failure reject the upload or degrade gracefully, and is that a decision someone made?
- **NULL in constraints.** Optional pairs (`amount` and `currency`, `valid_from` and `valid_to`) appear everywhere in banking schemas. "Both or neither" constraints are a classic place for the NULL-passes bug, and a migration test with one row per broken rule is how you prove the constraint does what it says.
- **Rendering stored rich text.** Anywhere an app shows text a user (or an AI agent) wrote, a structured format rendered element by element beats sanitising HTML. For an agent, the same applies to links in its answers: check the scheme again in the client, even if the server checked it.
- **Performance numbers that won't sit still.** The bimodal `--slow` result is what CI performance checks do too: one run proves little. Compare against the previous commit on the same machine, repeat, and report counts, not one number.
