## 4. Decisions and alternatives
| Decision | Alternatives | Why this one |
|---|---|---|
| `and e.dateUnknown = false` in the JPQL itself | Filter in Java after the query | The rule must hold for the `Limit` of 20 too: filtering after would return fewer than 20 while more exist. Same reason the seal clause lives in the query (CLAUDE.md mistakes table) |
| Keep a hidden cover when `coverMediaId` is `null` (`EraCovers.isHidden`) | Tell "left out" from "`null`" with `JsonNullable` or `Optional<UUID>` | The client was shown `cover: null`, so it can never mean to remove a cover it can't see. A tri-state field would change the generated TypeScript type and need a library. Documented in API_CONTRACT: `null` counts as left out |
| `isHidden` asks the same finder as `visible()` and signs nothing | Call `covers.of()` and check for `null` | `of()` presigns a URL only to throw it away; security.md says to presign only what the caller may see |
| Covers on the feed come from `GET /eras` (`useEras`) | Add `cover` to the feed's `WeekEraResponse` | No API change in a UI task; `/eras` is one small list; the feed doesn't wait for it, the initial fills the same 32 px tile until it arrives, so nothing moves |
| On this day tile is an icon (Image, BookOpen, Mic, FileText) | The first photo as a 40 px thumbnail (DESIGN.md) | A summary has no file URL (D-24), so a thumbnail would need a `GET /entries/{id}` per row, and a 40 px original fails the audit (Q29). 4.12's Recently deleted rows set the precedent |
| The feed waits for On this day before its first paint, and a failure counts as nothing | Draw the feed first and insert the row later | design.md §6: the row is above the first photo; arriving late would push the feed down |
| Below the first entry while the Opened row shows, through an `afterFirstEntry` slot on the first `WeekSection` | Render it between weeks | D-41 and the mockup put it after the first entry, which can be inside a long week |
| Cover picker in Edit only, reading the Era's weeks six at a time with `useQueries(weekQuery)` | A new "photos in an Era" endpoint; offer the picker on New Era too | D-36 "whenever the Era is edited"; a new Era has no weeks yet; reusing `weekQuery` shares the cache with the week page; no endpoint in a UI task |
| Radio tiles: a visually hidden `<input type="radio">` with a `peer` tile | `role="radio"` buttons with a hand-written roving tabindex | The browser gives arrow keys, one Tab stop and the checked state for free |
| The Eras list keeps the initial | Show covers there too | Not asked by the task; that screen passes the audit today and would fail *images* like the feed |
| Era line and chips now link to `/eras/<id>` | Keep `/eras` | 4.4 linked to the list only "until Era pages exist"; 4.9 built them |

## 10. Concepts to learn from this task
- **A rule in the query, not after it.** With `LIMIT 20`, a filter in Java after the query silently returns fewer rows than exist.
- **Absent versus null in a `PUT`.** Java records can't tell them apart; when the client cannot know the value, "unknown" and "none" may safely mean "keep".
- **`allMatch` on an empty stream is `true`** (vacuous truth): handy here, a classic bug elsewhere.
- **`useQueries` with `combine`:** several queries in parallel, each cached under its own key, returned as one derived object.
- **Native radio groups** give arrow keys, one Tab stop and `:checked`; a `peer` class lets the visible tile follow the hidden input.
- **Reserving space** by waiting for small late data before the first paint, so nothing shifts.
