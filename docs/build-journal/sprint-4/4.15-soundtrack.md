# Task 4.15: Soundtrack picker and player

> **Sprint:** 4 · **Commit:** `Sprint 4.15: Add the soundtrack field and the tap-to-load player`, on `phase-1-sprint-4` · **Status:** done (unattended); spec review passed with notes, two quick fixes made at close-out, the rest are follow-ups in section 9 · **Time taken:** about 40 minutes (12:12 to 12:50 AEDT, 26 November 2026)
> **Built:** an entry, a week and an Era can each get a Spotify soundtrack, by pasting a share link or by searching through our server, and every screen that shows one draws a placeholder row that loads Spotify's player only when *Play* is tapped.

## 1. The goal
[Task 4.15](../../SPRINT_PLAN.md#sprint-4-react-ui):
- **Do:** a soundtrack field on entries, weeks and Eras: paste a Spotify link (turned into a URI), or search through `POST /music/search` when it's available. Spotify's player shows as a placeholder until tapped, and only then loads.
- **Done when:** component tests cover pasting a link, picking a search result, search being unavailable (paste only), and no request to Spotify before the player is tapped.

Why now: the backend side has existed since task 3.14 (the `soundtrack` field on three resources, and the search endpoint, which answers `503` because this machine has no Spotify credentials). Capture (4.6), the Era form (4.9) and the week page (4.10) were already built, and each of them was careful to send the stored soundtrack back on every `PUT` (D-26), waiting for this task to give the user a way to change it.

## 5. How it was built
In review order:

- **`frontend/src/lib/spotify.ts`.** [`spotifyUri`](../../../frontend/src/lib/spotify.ts#L27) returns a discriminated union: `{ ok: true, uri, kind }` or `{ ok: false, reason }` with `not-a-link`, `short-link` or `wrong-kind`. It trims, accepts a URI as is, adds `https://` when there is no scheme, parses with `new URL` inside `try`, allow-lists the two hosts, drops the optional `intl-xx`, `embed` and legacy `user/<name>` segments, and requires exactly `<kind>/<22-char id>`. [`embedUrl`](../../../frontend/src/lib/spotify.ts#L68) builds the player's address only from a value that passes the server's own regex. The reason matters: `not-a-link` means "these are words, search for them", while the other two get a message.
- **`frontend/src/api/music.ts`.** [`musicSearchQuery`](../../../frontend/src/api/music.ts#L13) puts `skipToken` in place of the `queryFn` while `words` is `null`, keys the cache by the words (`queryKeys.musicSearch`), and turns retries off. `unwrap()` makes a `503` an `ApiProblem` whose `kind` is `music-search-unavailable`.
- **`frontend/src/assets/spotify-mark.svg` and `components/SpotifyMark.tsx`.** The path has `fill="currentColor"`; the component sets `text-ink` (or `text-on-band` on the Era band), so it is black in light mode and white in dark, never green (design.md §7). `?no-inline` keeps it a real URL, because Chrome refuses `<use>` on `data:` URLs (task 4.8 found this).
- **`frontend/src/features/music/SoundtrackPlayer.tsx`.** `playing` starts `false` ([line 24](../../../frontend/src/features/music/SoundtrackPlayer.tsx#L24)); until then the DOM holds the mark, "**Song** on Spotify" and a quiet *Play* labelled "Play the song on Spotify". After the tap the iframe is added and an effect focuses it ([line 30](../../../frontend/src/features/music/SoundtrackPlayer.tsx#L30)). A value the server wouldn't store draws nothing.
- **`frontend/src/features/music/SoundtrackField.tsx`.** The parent owns the value. `onChange` of the text field calls `spotifyUri` and takes a link at once ([line 155](../../../frontend/src/features/music/SoundtrackField.tsx#L155)); Enter is caught so it never submits the surrounding form (FormDialog, capture) and runs [`submit`](../../../frontend/src/features/music/SoundtrackField.tsx#L71). Once a search meets the `503`, a render-time state adjustment ([line 60](../../../frontend/src/features/music/SoundtrackField.tsx#L60)) switches to paste only: the *Search* button goes, the label becomes "Soundtrack: Spotify link", and an alert says why once. [`choose`](../../../frontend/src/features/music/SoundtrackField.tsx#L62) remembers a picked result's title in component state (the server never will) and moves focus to *Remove*; *Remove* moves it back to the text field. `focusRef` lets capture's *Song* button find whichever is shown.
- **Capture.** `CaptureForm.tsx` replaces `kept.soundtrack` with a `soundtrack` state ([line 141](../../../frontend/src/features/capture/CaptureForm.tsx#L141)) that goes into the draft, counts as unsaved, is sent on every save, and is reset from the server on *Load the latest version*. A restored pre-4.15 draft takes the entry's own soundtrack ([line 223](../../../frontend/src/features/capture/CaptureForm.tsx#L223)). The field sits under the tags ([line 685](../../../frontend/src/features/capture/CaptureForm.tsx#L685)); the phone add bar's fourth column is now *Song* ([line 820](../../../frontend/src/features/capture/CaptureForm.tsx#L820)). `draft.ts` validates it with the server's regex.
- **Weeks.** `api/weeks.ts` has `useEditWeek` with `WeekFields { title, soundtrack }` ([line 43](../../../frontend/src/api/weeks.ts#L43)); `WeekSummaryPage.tsx` shows the week's row under its header ([line 98](../../../frontend/src/features/week/WeekSummaryPage.tsx#L98)) and an *Edit week* dialog with both fields ([line 299](../../../frontend/src/features/week/WeekSummaryPage.tsx#L299)).

## 10. Concepts to learn from this task
- **Click-to-load facade** (`SoundtrackPlayer.tsx:24`): render a cheap placeholder and add the third-party iframe only on a user action. It keeps the page fast and, here, keeps a privacy promise. The mistake is to add the iframe hidden (`display:none` still loads it) or with `loading="lazy"` (it still loads when scrolled into view).
- **`skipToken`** (`api/music.ts:25`): TanStack Query v5's way to say "not yet". Unlike `enabled: false`, the types know the query function only runs with real arguments, and `refetch()` can't run it by accident.
- **Discriminated union results** (`lib/spotify.ts`): `{ ok: true, … } | { ok: false, reason }`. TypeScript narrows on `link.ok`, so `link.uri` can't be read on a failure. The mistake is returning `null` for every failure and losing *why* it failed.
- **Parse, then allow-list** (`spotifyUri`): normalise, parse with the platform's parser, then check host, path shape and id against exact rules. `text.includes('open.spotify.com')` would accept `evil.example/?open.spotify.com/…` (a test proves it is refused).
- **Adjusting state during render** (`SoundtrackField.tsx:60`): `if (condition && !flag) setFlag(true)` in the render body, React's documented alternative to an effect for state that follows another value. It must be guarded, or it loops.
- **Callback refs to two places** (`SoundtrackField.tsx`, *Remove* and the input): a `ref={(el) => { a.current = el; b.current = el; }}` keeps a local ref and a parent's ref in step. In React 19, `ref` is a plain prop on function components, so `Button` passes it on without `forwardRef`.
- **`sandbox` and `allow` on an iframe** (`SoundtrackPlayer.tsx:64`): `sandbox` removes powers (navigation of the top page), `allow` grants browser features (autoplay, encrypted media). `allow-scripts` with `allow-same-origin` is only dangerous for a same-origin frame.

## 12. At work
- **Parsing pasted identifiers** is everywhere in banking: a BSB and account number, an IBAN, a BPAY reference, a URL to a statement. The same order applies: normalise, parse, allow-list, and return *why* it failed so the UI can say something useful. A reviewer looks for `includes()` or a loose regex on a URL.
- **Third-party widgets** (chat, analytics, maps, a market-data chart) are often gated behind consent or a click for privacy and performance. The facade pattern, plus a test that no third-party request happens before the click, is what a privacy review asks for.
- **Rate-limited upstreams** (a credit bureau, a payments sandbox, an LLM API for your agent): don't retry a "not configured" or quota error, cache identical requests, and design the UI to degrade (here, paste only) rather than fail.
- **Full-replace `PUT`s** (D-26): every form that edits part of a resource must send the rest back. The week page now sends both fields; the old code copied `week.soundtrack` back by hand, which works only while nothing else edits it.
